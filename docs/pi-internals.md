# Pi internals MMP depends on

Design §6 (docs/pi-upgrade-design.md) used to say a file-path import of a module Pi doesn't export,
or a read of a private field, is forbidden. In practice the new TUI (`src/tui/`) needs several of
them -- pi-tui ships some of MMP's rendering primitives only as private class members, and a few
of Pi's own conveniences (external editor, clipboard paste, key bindings, the scoped-models picker)
live in files Pi's package "exports" map doesn't expose. The rule instead (see design §6): **allowed
only when registered here and covered by `test/pi-internals.test.mjs`**. That test reads this table
(by row `id`, first column) and fails if a row and the registry drift apart, and fails, for every
row, with a message naming the row when Pi's upgrade moves, renames or removes what the row depends
on.

## Not in this table

Several other comments in `src/` say "mirrors Pi's X, not exported" (`file-arguments.ts`, `update.ts`'s
`refreshModelCatalogs` mirror, `session-commands.ts`, `share-commands.ts`, `manifest-cli.ts`,
`auth-cli.ts`, `tools/group.ts`'s `dispatchToChild`). Those *reimplement* a small piece of Pi's
behavior in MMP's own code -- they never import or read anything from Pi at runtime, so a Pi
upgrade can't make them throw; it can only make them describe Pi's real behavior incorrectly. That's
design §3's "复制代码的漂移" (`vendor.json` drift check), a separate, not-yet-built mechanism, not a
reach-in covered by this table.

`src/tui/chrome.ts`'s `(this.editor as unknown as { focused?: boolean })` cast is *not* a Pi
internal either: pi-tui's `Editor.focused` is a public field (`components/editor.d.ts`); the cast is
narrowing MMP's own `EditorComponent` interface (which doesn't declare `focused`), not reaching past
Pi's access modifiers.
