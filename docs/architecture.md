# MMP 架构设计

这份文档只写原则：MMP 是什么、分成哪几层、每层归谁、新东西该放在哪。不写具体实现。实现细节和契约在 [development.md](development.md)，每条原则的来历在 [decisions.md](decisions.md)。

## 1. 定位

MMP 是**本地的主力 TUI 工具**：一个建在 Pi 之上的 coding agent 终端界面。（TUI 指在终端里运行的全屏界面。）

多模态素材的生产和创作是要提前准备的方向，不是现在的定位。做功能时为它留余地，时机成熟再改造。

## 2. 四层

```text
4  入口和界面      mmp 命令、交互界面、非交互入口          MMP 写
3  扩展            内置扩展和用户声明的第三方扩展           MMP 写内置的
2  装配            配置、项目信任、这次运行加载哪些资源      MMP 写
1  内核            模型、Agent 循环、会话、压缩、基础工具    Pi，锁定版本，不改
```

- 上层只通过下层公开的接口使用下层。用到 Pi 没公开的接口时必须登记并有测试。
- 所有运行模式走同一条启动路径，不为某个模式或某个扩展单开一条。各模式的区别只在加载哪些扩展：只和界面有关的扩展（专用视图这类）只在交互界面里加载。

## 3. 原则

### 3.1 内核不动

coding agent 的内核是 Pi。MMP 不 fork、不复制、不改它的行为，只升级。新能力先做成界面功能或扩展；做不成时才单独评估要不要动内核。

### 3.2 投入在两处：界面和内置扩展

- **界面**负责人怎么指挥和审查。
- **内置扩展**负责 agent 能做什么：工具、模型来源、对会话事件的反应。

装配层跟着这两处的需要改，本身不是目标。

### 3.3 界面的分工

> TUI 负责高频指挥、状态观察和快速审查；需要高视觉带宽时，打开与当前任务绑定的专用视图。

- 对话区常驻，用来下指令、看 agent 在做什么、快速过一遍结果。
- 完整的文件、渲染后的文档、图片、视频这类内容，在专用视图里看，不用离开 MMP 去开编辑器。
- 专用视图要和当前任务绑定：打开时看到的是这次任务相关的东西。
- 目标不是在终端里重做一个编辑器。人的工作是指挥和审查，界面为这两件事服务。

### 3.4 给 agent 的能力和给人看的界面分开

浏览器操作、电脑操作这类能力是 agent 的工具：agent 能操作、能拿到反馈。它们属于扩展层。界面只负责把 agent 做了什么显示出来，并让人能接手。

### 3.5 扩展一视同仁

内置扩展用的接口和第三方扩展一样。不为某一个扩展在启动流程里加专门的判断或后备逻辑；需要时改的是对所有扩展都成立的通用步骤。

两个扩展不能注册同名命令，内置的也一样：启动时就报错，说清是哪两个，不让一个名字悄悄指向别的东西。

### 3.6 扩展有自己的版本

每个内置扩展有自己的版本号、更新记录和 tag 前缀，和 MMP 的版本分开。扩展的版本只在它自己有改动时才变；MMP 的发版说明写明带了哪些扩展版本。这样一个扩展以后可以整体搬出去单独发布。

### 3.7 配置只属于 MMP

不读 Pi 或其他工具的配置，不认用户给 Pi 设的环境变量。项目里的配置要先被信任才读。加载什么由 Manifest 显式声明。会影响模型能做什么的内置能力（子任务、MCP、Hooks）默认开启，可以关掉；只是界面功能的内置扩展（如 `/preview`）不改变模型看到的东西，始终存在。

### 3.8 失败要看得见

不静默兜底，不吞错误，一个失败不能表现成另一个失败。

### 3.9 对外只有 mmp

参数、子命令、帮助和报错都是 MMP 自己的。功能优先和 Pi 对齐，不同的地方写明理由。

## 4. 新东西放哪一层

| 想做的事 | 放哪 |
|---|---|
| 显示、交互、快捷键、命令、专用视图 | 界面，或只在交互模式加载的内置扩展 |
| 新工具、新的模型来源、对会话事件的反应 | 内置扩展 |
| 配置怎么找、怎么合并、是否可信 | 装配 |
| 改 Agent 循环、压缩、会话格式、工具执行语义 | 内核：现在不做 |
