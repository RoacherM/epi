# 对话区单列排版与耗时条设计

> **2026-10-22 修订（0.1.24）**：用户看过 0.1.23 实际效果后决定「都应该支持终端全宽」——正文、工具调用行、失败行、你的消息条都改用终端全宽，不再限 76 列（`src/tui/measure.ts`）。耗时条因此落在终端右边界，和表格、代码块、状态行、输入框同一条右边界。下文的 76 列/版心描述是 0.1.23 的设计，留作记录。


状态：**已确认**（2026-10-22：§5 第 1 条用户定 h/m/s；第 2、3 条按建议默认：用户消息条收进版心、版心 76 列，"ok。先新增功能"）。接续 [tui-transcript-layout-design.md](tui-transcript-layout-design.md)（0.1.22 已实现的回合脊柱、单行工具调用、76 列正文）。

来源：用户 0.1.22 实际使用截图（宽终端，约 300 列）。原话："修复下布局右侧的时间……我建议排版都在一列，你设计下？然后可以简约一点，比如不是文本而用图表显示"。

## 1. 问题（截图里看到的，对照过代码）

0.1.22 把工具耗时写在调用行的末尾，紧跟命令之后（`tools/common.ts` 的 `CallLine.tail()`，前面留 2 个空格）。命令长短不一，所以耗时的横向位置也跟着乱跳：

- 短命令（`read … · 1 line  65ms`）的耗时在第 50 列左右；
- 被截断的长命令，耗时贴在终端最右边，宽终端里在第 300 列附近；
- 同一组连续的调用里，耗时上下对不齐，没法一眼比较哪一步慢。

正文已经限宽到 76 列，工具行却铺满整个终端，回合在视觉上分成了宽窄两列。用户消息条的时钟（`10:59 AM`）同样贴在终端最右边。

0.1.22 设计时刻意没把状态右对齐到终端边缘（R4 推论：宽终端里会漂到 200 列开外，和所在行失去关联）。这次的修法不是右对齐到终端边缘，而是对齐到一条**固定的列**。

## 2. 方案：一列版心 + 耗时条

### 2.1 版心

整个回合排在同一列里：左边是第 1 列的脊柱，右边界是正文限宽的右边界，也就是内容第 5 列起 76 列，到第 81 列为止（终端更窄时到 `width - 1`）。

| 元素 | 0.1.22 | 改后 |
|---|---|---|
| 正文 | 限宽 76 列 | 不变 |
| 工具调用行 | 铺满终端，耗时紧跟命令 | 截到版心右边界；耗时条贴在版心右边界，所有行同一列 |
| 失败行 `✗ exit 1 · …` | 铺满终端 | 截到版心 |
| 用户消息条 | 灰底铺满终端，时钟在最右边 | 灰底宽度等于版心，时钟在版心右端 |
| `Worked for` | 不变 | 不变 |
| 代码块、表格、Mermaid 图 | 全宽 | 不变：它们是数据，内容本身需要宽度（R1） |

代价：宽终端里长命令能看到的部分变少了（宽终端原来能显示 280 列，改后约 70 列）。完整命令仍可通过 `Ctrl+O` 展开、单击打开全文悬浮窗或 `/trace` 查看。命令真正有区分度的部分在开头，0.1.22 已经去掉了 `cd <cwd> &&`，所以 70 列通常够用。

### 2.2 耗时条

工具调用行的耗时数字换成一个 4 格宽的条，按**对数刻度**，每格代表一个数量级：

| 格 | 区间 |
|---|---|
| 第 1 格 | 10ms – 100ms |
| 第 2 格 | 100ms – 1s |
| 第 3 格 | 1s – 10s |
| 第 4 格 | 10s – 100s |

格内用八分块（`▏▎▍▌▋▊▉█`）按对数位置填，没填到的格是暗色 `·`。不到 10ms 一格都不填，只显示 `····`，表示几乎瞬时（2026-10-22 修订，用户确认：0.1.23 原来显示最细的 `▏`，终端把它画满整格高，连续几个很快的工具会上下连成一条竖线，看起来像分隔线）。超过 100 秒条满格，后面补上暗色数字（`████ 2m20s`），因为满格以后条已经区分不出长短了。

数字只用 h、m、s 三个单位（用户定，2026-10-22："支持h/m/s这三个单位即可"）：`1m40s`、`2m20s`、`1h5m12s`；为零的低位省掉（`2m`、`1h`、`1h5m`）。补数字只发生在 100 秒以上，所以用不到毫秒。同一个格式也用于 `Worked for` 和思考行，改的是共用的 `formatDuration`（`chrome.ts`）：它现在没有小时，一小时以上会写成 `61m40s`。60 秒以内保持现有的一位小数（`12.3s`、`∴ 7.6s`）。

为什么用对数刻度：工具耗时从几毫秒到几分钟，跨 4–5 个数量级，线性刻度下除了最慢的那个，其余全是一条细线。对数刻度下，几乎瞬时、零点几秒、几秒、几十秒正好落在不同的格子里，扫一眼就分得清。

按截图里的真实耗时模拟（版心 76 列）：

```text
 ├─$ (npm view ondine name version description repository.url license 2… ██▍·
 ├─$ cd /tmp && rm -rf ondine-try && mkdir ondine-try && cd ondine-try … ██▋·
 ├─$ cd /tmp/ondine-try && du -sh package && du -sh package/dist/intern… █▌··
 ├─$ cd /tmp/ondine-try/package && cat dist/cli/Ascii.d.ts dist/cli/Ter… ▉···
 ├─$ cd /tmp/ondine-try && npm init -y >/dev/null && npm install ondine… ███·
 ├─◆ read /tmp/ondine-try/flow.png · 1 line                              ▉···
 ├─$ npm test -- --run                                                   ████ 2m20s
 │
 │ ∴ 3.1s
 │   装进临时目录，和现在的引擎用同一批图做个对比：
 ╰─ Worked for 34.8s
```

细节：

- **颜色**：条用 `dim`，空格 `·` 用 `borderMuted`。成功的耗时是常态信息（R2、R4），条只表达相对长短，不抢眼。
- **受保护的尾部不变**：`· +36 lines`、`· 4 lines`、`· +3 −1` 这类摘要仍紧跟在命令后面，截断时永远保留（0.1.22 的 `fitWithTail`）；只有耗时移到右边那一列。
- **运行中**：条按已经过去的时间实时变长，替代 0.1.22 运行时什么都不显示的空尾部。只有回合末端 8 行会动（0.1.22 的约束：屏幕外的行变化会触发整屏重绘），运行中的工具本来就在末端。
- **失败**：调用行不画条（同 0.1.22 失败时不显示耗时），下一行红色 `✗ exit 1 · …` 不变。
- **只读工具合并行**（`◈ Read 3 files`）：条表示合计耗时。
- **确切数字**：`Ctrl+O` 展开时，条后补上暗色数字；`/trace` 里一直有精确耗时；`Worked for` 是整个回合的总时间。
- **`!cmd`**（`bash-block.ts`）：同一套规则。

### 2.3 不变的部分

- 思考行 `∴ 7.6s`：这一行只有这一个信息，保留数字，不画条。
- 底部状态行（`34.8s ↓755 · 22 tok/s`）属于界面外框，不在对话区，不动。
- 模型看到的内容不变，`model-snapshot` 无差异。

## 3. 改动点

| 文件 | 改什么 |
|---|---|
| `src/tui/markdown-layout.ts` | 导出版心右边界的计算（`CONTENT_COLUMN + measure`），供其他组件共用，避免各写一个 76 |
| `src/tui/tools/common.ts` | `CallLine`：尾部拆成两部分，摘要仍跟在命令后，耗时改为版心右边界上的条；新增 `durationBar(ms)` |
| `src/tui/bash-block.ts` | `!cmd` 调用行同上 |
| `src/tui/tools/group.ts` | 只读合并行用合计耗时画条 |
| `src/tui/chrome.ts` | 用户消息条宽度改为版心，时钟放在版心右端 |
| `src/tui/spine.ts` | 无需改：脊柱只改第 1–2 列 |

## 4. 测试与验收

- `durationBar`：各数量级边界（9ms、10ms、99ms、100ms、1s、10s、99.9s、100s、2m20s），格数和八分块正确，宽度恒为 4 格（满格后带数字的除外）。
- `formatDuration`：59.9s、60s → `1m`、100s → `1m40s`、3600s → `1h`、3912s → `1h5m12s`、7200s → `2h`。
- 对齐：40/80/120/230/300 列下，同一组工具行的耗时条起始列相同；每行 `visibleWidth ≤ width`。
- 受保护尾部：长命令加 `· +36 lines` 时，摘要和条都在，截断的是命令。
- 运行中：条随时间变长，只在回合末端；完成后定格。
- 失败行、`Ctrl+O` 展开显示数字、`/resume` 回放与实时一致。
- 快照测试按改动更新；`model-snapshot` 无差异。
- 实测：Orca 真实终端，在宽终端（约 300 列）和 80 列下各跑一个多工具回合，日夜两个主题。
