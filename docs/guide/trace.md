# Trace：看这次会话执行了什么

[← 使用文档](README.md)

`/trace` 打开一个整页的执行轨迹，不用离开 Epi：

- **瀑布图**：列表里每一行步骤右边都有一条条。默认是**瀑布**：每条有一条淡色时间基线，执行段用粗线压在基线上，左端是开始时刻、右端是结束；只有真实起止的步骤画成段，只有时刻的画一个点。`v` 切成**时长柱状图**：每行条长只按耗时，全部从同一列开始，直接比较长短。两种都**只取当前屏幕里看得见的步骤**，滚动时跟着重算。
- **步骤列表**：一行一步，类型、对象、状态、耗时，右边是瀑布条。
- **详情**：选中一步看 Summary / Payload / Result / Schema / Timing 五个栏目。

它是内置扩展 `epi:trace`，只在交互界面里加载，模型看不到它。设计见 [trace-design.md](../trace-design.md)。

当前版本：**0.1.0**。

## 打开与导航

整页打开，`Esc` 关闭并回到对话（草稿不受影响）。

| 键 | 作用 |
|---|---|
| `j` / `k` | 选择上一步 / 下一步 |
| `v` | 在瀑布（按时间定位）和时长柱状图（按耗时长短）之间切换 |
| 回车 | 打开详情 |
| `Tab` | 在列表和详情之间切换焦点 |
| `←` / `→`、`1`–`5` | 在详情里切换栏目 |
| `/`、`n` / `N` | 在详情里搜索、跳下一个 / 上一个 |
| `g` / `G` | 到最前 / 最新（`G` 也重新跟随） |
| `Esc` | 关搜索、关详情、关页面 |
| 鼠标 | 点一行打开它的详情；滚轮滚动 |

宽 ≥ 120 列时列表和详情并排；更窄时详情整页显示，返回仍停在原步骤。

## 时间是怎么来的

- 模型响应：用 Pi 记录的响应起点和 `durationMs`，标注为「SDK 记录」。
- 工具：`execute()` 耗时来自工具结果；时间轴上的跨度来自本进程观察到的 `tool_execution_start/end`。
- 工具结果的时间戳是整个并行批次完成后创建结果对象的时刻，**不能**减去耗时当成真实开始时间。没有观察到起止的历史工具只显示执行耗时和一个结果时刻的点，详情写明「执行起止未记录」。

## 兼容性

不按模型名字做分支。缺失、明确为零、流式暂计分开显示；`reasoning` 已经包含在 `output` 里，`cacheWrite1h` 是 `cacheWrite` 的子集，不会重复计。Schema 从会话的 system 消息按调用前状态回放，是「调用当时」的声明；当前工具注册表只作为单独的参考，不冒充历史定义。

## 尚未实现

- 观察摘要不落盘：重启后新会话仍有历史步骤，但工具生命周期区间只在本次进程里观察。
- 完整子代理（task）子轨迹：只显示已有的任务调用信息。
- `/review` 之间的互相定位。
